# Подключение отдельной базы «БлагоТвори. Кемь»

Новый сайт не должен использовать базу проекта «Добро.Медиа».

## 1. Создать новый проект Supabase

В новом проекте открыть SQL Editor и выполнить по порядку:

1. `supabase/blagotvori_schema.sql`
2. `supabase/blagotvori_seed.sql` — только если нужны стартовые демонстрационные вакансии.

## 2. Добавить переменные в отдельный проект Vercel

Использовать пример `.env.blagotvori.example`:

- `BLAGOTVORI_SUPABASE_URL`
- `BLAGOTVORI_SUPABASE_SERVICE_ROLE_KEY`
- `BLAGOTVORI_ADMIN_PASSWORD`

Переменные старого сайта `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` для нового проекта не использовать.

## 3. Проверить работу

После повторного развёртывания:

- главная страница должна показывать вакансии без пометки «демонстрационный режим»;
- форма «Стать волонтёром» должна сохранять заявку;
- `/admin-blagotvori` должен открываться по новому паролю;
- новая заявка должна появляться в разделе «Заявки волонтёров»;
- после подтверждения часов должны сохраняться фактические часы и отметка о переносе на Добро.рф.

## 4. Безопасность

- Service Role Key хранится только в переменных Vercel и никогда не публикуется в браузере.
- В базе включён RLS, прямой публичный доступ к таблицам не выдаётся.
- Все действия волонтёров и организатора проходят через серверные API-маршруты сайта.
